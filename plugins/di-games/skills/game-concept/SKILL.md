# game-concept: stage 0, from a concept to the picks

- **Makes:** `docs/concept-analysis.md` in the game's repo, one page.
- **Gate (done when):** the owner has answered every pick. Nothing is designed or built before that.
- **Who:** game-designer.

## Method (cited)

- Start from the feelings, not the features. The MDA frame (Hunicke, LeBlanc, Zubek, "MDA: A Formal
  Approach to Game Design and Game Research", AAAI Workshop on Challenges in Game AI, WS-04-04, 2004)
  says rules (mechanics) make play (dynamics) make the feelings (aesthetics). Players meet the feelings
  first, so the analysis works backwards: the feeling, then the play that makes it, then the rule.
- This is the first step of the playcentric loop: set the player-experience goals before any prototype
  (Fullerton, *Game Design Workshop*, 5th ed., CRC Press, 2024).

## Steps

1. Read the whole concept as given. A picture: open it and look (the Read tool shows images). Read for what
   the person means, not only the words: English may not be their first language, so restate each ask in
   one line in your words.
2. Sort what you found into three lists: stated (in the concept), implied (a fair reading), missing.
3. Write the game in one sentence. If you cannot, that is the first pick.
4. Write up to three target feelings. For each: the feeling, the play that should make it, the rule behind it.
5. Find two to four neighbouring games (same mechanic or same setting). For each: the mechanic, the look of
   its opponent, and a source you opened in this session. The point is to avoid copying: mechanics and ideas
   are free; other games' characters, art, music and names are not. Roblox's IP policy was not read when
   this skill was written (unchecked): read it before any look is taken from another game.
6. Turn every unknown into one of three things: a fact you find out yourself (read a file, open a page), a
   default you choose and name (cheap to change later), or a pick. Only a pick goes to the owner.
7. Write each pick as: the question in plain words, two or three options with what each costs, and the
   default. At most five picks. Never ask "does it look right?": if you can check it, check it. The engine
   (Roblox, di.iiii, or both) is its own pick, because the rules hold on both.
8. Save the file. Put the pick list first in your reply to the caller.

## File layout (`docs/concept-analysis.md`)

1. The concept in one sentence
2. What the concept shows (stated, implied, missing)
3. What the players should feel (up to 3: feeling, play, rule)
4. Neighbouring games (mechanic, opponent's look, source, date read)
5. Facts found out and defaults chosen (one line each, with the source)
6. Picks for the owner (P1, P2 ...): question, options, default

## Rules

- **An open owner decision stops the next stage.** Say which pick blocks which stage.
- Mark anything that is not in the concept as "not in the concept". Do not invent a story, a name or a look.
- Keep the concept's own look and voice. Do not swap in a template look.
- A source you did not open in this session is "unchecked", on the same line.
