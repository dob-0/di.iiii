C — In the account button, carried by ?lang=

The switch lives in the corner where di.iiii already keeps its floating account button, bottom-right: a two-word chip on the button's edge, and the first row of its menu. Today that button is drawn only on signed-in surfaces; public routes (landing, wiki, a public space) do not load it, so this concept puts a light chip in the same corner there. A shared link carries ?lang=hy; otherwise the choice is the person's, kept on their account or their device. No new header element anywhere.

Where it sits
Bottom-right, on the floating account button (src/components/AccountButton.jsx): a two-word chip on its edge, and the first row of its menu. That button is rendered by AuthGate, which public routes do not load (it pulls in MUI; kept off the public bundle since the 2026-07-17 perf audit), and 5 routes in src/RootApp.jsx pass showAccountButton={false}. So C needs a light, MUI-free chip in the same corner on those routes, and the same row in Preferences. Nothing is added to any header.
What it remembers, and how
Signed in: the account (serverXR user preferences), on every device. Signed out: localStorage["di.lang"] on this device. A ?lang=hy in an address wins for that visit only and is not saved unless the visitor then presses the switch.
What the address does
Normally nothing. The share and copy-link actions add ?lang=hy when the sender is in Armenian, so the receiver opens it in Armenian. Routes, space names and existing links are untouched; no slug has to be reserved.
What it means for search
Google Search Central lists URL parameters (its example ?loc=) as a possible structure but not recommended; hreflang can point at ?lang=hy addresses and the same bidirectional set (en, hy, x-default) is required. It works, at the weakest of the three shapes Google names; and any internal link that forgets the parameter drops a crawler back into English, so every link the frame draws has to carry it.
A page with no Armenian yet
Frame in Armenian, body in English under the same one line: Այս էջը դեռ հայերեն չունի։ Ստորև՝ անգլերեն։ The page leaves hy out of its hreflang set until it has an Armenian body.
How the work is left untouched
The parameter is consumed by the frame and removed from what the work is loaded with, so a work that reads its own query string never sees lang. No message, no attribute; the container carries translate="no"; the work's lang is the artist's. Because the switch floats over the page, it is the one concept whose button sits over the work — it must never be drawn into a capture of it.

Typeface: the platform's Inter is a latin subset (48,256 bytes) with no Armenian glyphs, so Armenian here falls back to the system font, as it would on the live site today. All Armenian copy in this sketch needs a native speaker's check.
