The di.iiii Lexicon

Every word in the product is named after how it was built, not what it is to a person. That is the whole disease. Here is every word, every meaning it currently carries, and the one meaning I think it should keep.

The short version

“Studio” and “Raw” are not two places. They are two codebases. A visitor is being shown your repository structure as if it were a floor plan. Raw is already invisible on its own page — the word appears nowhere at /open/raw, only in the URL and the footer. Finish that: stop printing it.

“Space” carries six meanings because it was the first noun and everything got hung on it — the tenant, the 3D scene, a node type, a browser-local record, a synced static site, and a React route. It cannot be fixed by renaming; it is fixed by moving four of those jobs onto words that already exist.

Almost none of this is a code change. The identifiers can stay exactly as they are — space alone appears 5,607 times in source. What needs to change is the ~200 sentences a person actually reads.

I · The dictionary

space 6 senses 211 in wiki · 72 in UI
  1. A tenant: an address, a guest list, an asset store. serverXR/src/db.js:6 — the spaces row: owner, access, invites, sync keys
  2. A 3D scene in its own right. db.js:13 scene_version + spaceStore.js:99 scene.json — a space owns a scene with no project involved. This is the V1 fossil.
  3. A node type inside a document. nodeRegistry.js:752 — id universe.space, label Universe. The id and the label are already different words for the same node.
  4. A browser-local record with no server behind it. src/storage/spaceStore.js:3 — and useSpacesController.js:179 says it out loud: Created a local space instead.
  5. A GitHub-synced static site (“linked space”). scripts/space-sync.mjs:3 — used 4× in the wiki, never once defined for a reader
  6. A React route (“code space”). src/studio/utils/codeSpaces.js:11 — Spaces whose scene is CODE rather than a project document; badge code space at StudioHub.jsx:315
Keep — but only sense 1

A space is a place that is yours: it has an address, a guest list, and things inside it. That is a sentence a stranger understands, and it is exactly what the database says.

Senses 4–6 are not really meanings, they are implementation notes leaking into copy. “Linked space” and “code space” are things only you need to know; a visitor should just see a space. Sense 2 is the honest problem — the schema really does let a space hold a scene with no project — and that is a retirement job, not a wording job.

project 5 names 57 in wiki · 43 in UI · 0 on the landing page

The opposite problem to space: one thing wearing five names.

  1. project db.js:28 — the row. Hard-owned by one space: space_id … ON DELETE CASCADE
  2. scene wikiContent.js:25 — A project is a single scene/document inside a space.
  3. document same sentence. Also README.md:75 the editable document inside a space
  4. page wikiContent.js:163 documents the URL as /<space>/<page> — the same slot the router calls projectSlugSegment

Keep “project”, kill the four synonyms

It is the word in the database, in the API, and in /p/{id}. Renaming it would be enormous and would buy nothing — but the synonyms are pure copy and cost nothing to remove.

The sharper problem: a visitor meets the word “Projects” as a page heading (StudioHub.jsx:208) having never once seen it on the landing page. The landing sells spaces and worlds; the hub then asks about projects. Introduce it, or accept that the first screen after sign-in speaks a word the front door never taught.

Keep sense 1 only — Studio is a room, not a lane

You have already written the good version yourself: “Studio is a room on the same desk.” Commit to it. Studio is the name of a place inside the workspace, the way “kitchen” is a room and not a brand.

The worst single artefact in the product is on one page: RawHub.jsx:261 has a button reading open studio that creates a Studio node, and RawHub.jsx:312 has a button reading studio that navigates to the Studio lane. Same word, same screen, unrelated actions. (Verified in the running code.)

Raw retire the word 18 in wiki · 40 in UI

Raw is a name you gave a branch. It has never been explained to a visitor, and the landing page's own source comment admits it: “the lane name is vocabulary a first visitor does not have yet” (LandingPage.jsx:245).

  1. The node-first editor. Footer link Raw · StudioHub.jsx:217 button Raw · RawHub.jsx:211 heading di.iiii raw
  2. An adjective for a kind of project. RawHub.jsx:52 — No raw projects in this space yet. Implies “raw” is a project type, which it is not.
  3. Ordinary English: unparsed, unformatted. PreferencesPage.jsx:596 Storage & Raw Snapshot sits 12 lines below Raw Path (:584) — one is English, one is the lane, nothing distinguishes them
Stop printing it. Keep /raw in the URL forever.

You are three edits from this already being true. I checked /open/raw on staging as a plain visitor: the word “Raw” appears nowhere on the page. What you read is World, welcome, Enter Studio. It survives only in the footer link, the StudioHub button, and the RawHub heading.

The URL is a different matter — links exist in the wild, and /seed is already kept alive as a legacy alias (rawRouting.js:10). Routes are permanent; words are not.

Two words, two honest referents. “Entity” should not survive anywhere a person can read it — it is the one word here that is pure ECS jargon, and it sits in the sentence the Inspector shows on every single selection.

world · room · desk 9 senses between them world: 17 · room: 19 · desk: 6

world currently means: a Studio panel · a node type · a space · your finished artwork · planet Earth (together across the world, LandingPage.jsx:385) · and a coordinate frame (world position is kept, wikiContent.js:212).

desk is your newest metaphor — 6 uses, one of them in the primary CTA subtitle — and it collides with two node types actually named 2D Desk and 3D Desk (nodeRegistry.js:779, :805).

room = the 3D place you are inside. World = the node's name, nothing else.

“The room” is already the node family label you shipped yesterday, and “the room follows” is already in the starter text. It is doing well; let it take the whole job.

On desk: either commit or drop. A metaphor used six times, never defined, and colliding with a node label is currently costing more than it earns. My advice is drop it from copy and rename the node types if you want to keep the word for the surface.

II · Words that are simply dead

“Beta” is still a documented, published route

The lane was deleted 2026-08-06. public-README.md:36 still publishes /<space>/beta in a route table on the public repo's front page, and README.md:60 still instructs: “Use /<space>/beta for experimental or node-first work.” Also public-README.md:78, 85, 107 and README.md:38, 41, 73. Verified. Anyone arriving from GitHub is being sent to a route that no longer exists.

“lane”, “surface”, “V1”, “seed”

Internal words for editor generations. lane reaches the reader in the wiki (asked a first-time visitor to choose a lane before they knew what a lane was — the article explaining the fix uses the word it is retiring). seed is a live legacy URL alias. None of these should appear in anything a user reads; all are fine to keep in docs/.

Two landing-page instructions point at panels that do not exist

Step 02: “Use the Library panel to add 3D shapes” — the window is called Create. Step 03: “Tweak with the Inspector on the right” — Studio's own copy sends you to the Scene window. LandingPage.jsx:54–55. Verified. These are the four sentences that tell a stranger how to use the product.

One console, two names

The wiki calls it Ops Graph → Manage (wikiContent.js:437) and /admin → Manage (wikiContent.js:276) in the same article set.

III · The one decision this forces

Studio: a room, or the whole building?

Everything above assumes Studio is a room — a place inside the workspace, next to Color and Cube in the palette. That matches what is already on screen and what you already wrote.

But there is an unsigned spec in the repo that assumes the opposite. docs/architecture/SPEC_url_architecture_and_tree_addressing.md proposes splitting the product across two hosts, and names the creator host studio.di-studio.xyz — which makes Studio the name of the entire authoring side of the platform. Sign that spec and “Studio the room” has to be renamed instead.

These two cannot both be true. It is the only naming question here that is genuinely yours and not mine — and it is worth answering before any of the copy work below, because it decides which word moves.
