The Raw Workshop Map

2026-08-20 · measured at origin/dev 951da5b8 · companion to the product audit "What Raw Is Now" · goal: every future Raw change small, safe and fast

This is a map of the workshop, not the repertoire. Six lanes of investment, each measured from the real code and the real git history, ranked so that each one makes the next cheaper. The through-line: today Raw is honest but hand-wired — a new operator touches ~12 files, half of them with no test that fails if you forget, every parallel PR collides in the same three files, and the answer to "did my change work" costs a 4m41s CI gate dominated by one un-sliceable test run.

EFFORT S · HOURS

Lane 1 · clean the yard first

Resolve where truth lives

The main checkout's dev is 46 commits behind and 2 ahead (the stranded vocabulary pass: docs/ai/vocabulary.md + a 370-line copy test + renames touching RawEditor.jsx). Every session starts by rediscovering this. 13 worktrees against a budget of 6, 28 unmerged branches against 8.

  • Rebase the vocab commits onto current dev and PR them — or park them on a named branch. Owner's one decision; the conflict grows daily.
  • Fast-forward the main checkout to origin/dev once the vocab strand is off it.
  • npm run state --sweep + an owner pass over the named trees (rawadmin, raw-ws, dijetnode, inscription-mark, design-loading-unify, agents-upgrade: park or PR each).

Buys: every future session starts on truth instead of archaeology. Nothing else on this map is safe to start before the vocab strand is rescued — it touches the same files Lane 4 will split.

EFFORT S · 1–2 SESSIONS

Lane 2 · stop the noise collisions

Defuse the generated-file conflict magnet

nodeAnatomy.generated.js (851 lines) indexes line numbers into three source files, so any edit anywhere above a node's code renumbers everything below it — two branches touching unrelated nodes both rewrite the whole file and conflict on code neither changed. It was in 10 of 13 wave diffs.

  • Re-key the generator (scripts/sync-node-anatomy.mjs) to stable anchors (AST node boundaries per type) so unrelated edits don't touch other types' entries — or regenerate post-merge in CI so the file is never hand-merged at all.
  • Same session: make CI's check:node-anatomy failure message say the fix (npm run docs:anatomy:sync) — today a contributor who forgot gets an undiagnosed red.

Buys: parallel Raw agents stop paying a merge-conflict tax on every pair of PRs. Highest ratio of pain-removed to lines-changed on the map.

EFFORT S→M · STAGED

Lane 3 · one place to add an operator

The registry becomes the whole truth

Half the add-a-node checklist is silent: the runtime compute case (a missing one silently carries a stale value down the wire), the viewport render case (a type that draws nothing — already shipped once as audit finding #22), window routing, the ACTIVE_MARKER_TYPE_IDS list, the room-summon exception. Stage the collapse; each stage is its own PR:

  • A — registry fields for the data-shaped facts (cheap, do first): activeMarker: true, summonsRoom, window default position move onto the entry; the scattered lists become lookups. Kill three silent sites with data.
  • B — colocate render3d: the viewport switch (14 cases) is already pure (node, values, assetMap) → JSX; it moves onto entries via per-family .jsx modules with a barrel (the JSX file-extension boundary forces the per-family split of the 1,952-line registry anyway — one move, two wins).
  • C — colocate compute: the runtime switch (30 cases) is uniform, but the bodies need evaluateNodeInput — inject it via the context argument to dodge the import cycle the code already documents dodging once (the 'studio' case comment).
  • D — window routing stays a dispatch, becomes a map: renderViewNodeContent's 16 branches close over live editor state, so full colocation is wrong here — but a type→component map with one explicit props bundle is separable, and it's the honest boundary between registry data and editor wiring.
  • Guard, same lane: extend the authoringOnly staleness check to viewport-only and window-only implementations. This blindness shipped the same bug three times (time, desk.3d, monitor). After stage A–B the check gets trivial: an entry with render3d or compute must not carry the tag.

Buys: "add an operator" collapses from ~12 files / 5 silent traps to one family module + tests + wiki, with staleness impossible. This is the lane that makes the whole phase-2 operator backlog (logic, lag, noise, audio, materials, geom.array) cheap instead of 12-file slogs.

EFFORT M · SEQUENCED

Lane 4 · split the rooms everything squeezes through

RawEditor, raw.css, and the hooks precedent

The repo already knows how to do this — the golden rule "extract logic to hooks, keep components render-only" took PreferencesPage from 1,457 lines to 443. It has never been applied to Raw. The measured seams, clean first:

  • Clean extractions from RawEditor.jsx (2,220 lines): useRawPaletteCommands, the renderViewNodeContent map (Lane 3D), the example builders, remaining window-geometry math into windowLayout.js. Split RawEditor.test.jsx (1,042 lines) in lockstep.
  • Tangled — extract with care, not first: scope navigation (closes over five state vars) and the live-output handlers, where closure identity itself is the recorded bug class (two known-fixes entries). Lane 5's registry move takes live outputs out of the component entirely — do that instead of extracting the handlers.
  • raw.css (5,062 lines): the ~35 section headers already map to component boundaries; the split is mechanical. cssBraceBalance.test.js already scans every file; colourRoles.test.js hardcodes raw.css and must switch to concatenating the set — same PR.

Buys: parallel sessions stop colliding in the two files 9-of-13 and 6-of-13 PRs touch; the next agent edits a 300-line module instead of steering a 2,220-line component.

EFFORT S THEN M

Lane 5 · one clock, one capture bus

Re-home the state that blocks features

The code already contains its own templates: liveWorldNodeIdByScope proves "one fact in the doc, every window reads it"; modelClipRegistry.js is a ready-made external-store shape; presence proves a per-viewer channel. In order:

  • Clock epoch into workspaceState — write clockEpochMs once when the first Time node appears; every window computes elapsed locally. Four files (projectSchema.js, useGraphClock.js + test, one call site). Unlocks multi-window Time phase sync and is the exact primitive cues/timeline needs for "when did this show start". Do this one first — it proves the pattern for pennies.
  • liveOutputRegistry module on the modelClipRegistry shape, consumed via useSyncExternalStore — RawEditor sheds its buggiest closure plumbing, and /out's hardcoded liveOutputs={null} becomes a real subscription. Honest limit: this makes capture reachable within a tab; a separate /out tab still needs a transport (BroadcastChannel first, WebRTC when it matters).
  • Scope stays put — re-homing navigation was a deliberate 2026-07-17 product decision; don't reopen it as a side effect. If it ever reopens, it's per-viewer state, not a shared field.

Buys: the wall that every "live" feature has hit three times (clock, capture, feedback) gets its first two doors. Inter-frame state for lag/feedback nodes becomes a follow-on, not a rewrite.

EFFORT S · PARALLEL-SAFE

Lane 6 · a loop you can trust, faster

Sharpen the dev loop and close the guard gaps

  • npm run test:raw — a named vitest slice (src/raw src/project/graph src/project/nodeRegistry*). The full run is 2m56s of a 4m41s gate and there is no first-class way to run just Raw's ~40 test files. Minutes to add, paid back every iteration.
  • Put /out and a seeded /open/raw into verify:surfaces' default sweep. The show-machine route currently has zero automated visual coverage, and its unit test mocks the whole viewport — the /out orbit-leak defect lived exactly in that blind spot.
  • One real touch contract for the palette path in check:input (which today has zero Raw references) — the pointerdown-vs-click class already shipped once and was found by a human.
  • An /out integration test with the real RawViewport — pins the OrbitControls branch and the camera handoff.
  • A currency check for rawGuide.js/USER_MANUAL — even a soft one (guide section ids must reference surfaces/commands that exist) turns silent doc rot into a red. Pairs with the already-owed Help rewrite from the product audit.

Buys: the verification charter's "look at it" standard gets automated eyes on the two surfaces that matter most for shows, and the inner loop drops from minutes to seconds for most changes.
