   tap-tap connect, discoverable Duplicate.
3. **Space that works** — delete ~700 dead css lines; spacing scale +
   density var; card geometry single-sourced JS→CSS; topbar centre carries
   computed state; honest bottom reserves.
4. **Phone as a main instrument** — tap-tap connect, 44px palette rows
   (SHIPPED), toolbar avoids the selected card, reachable undo, pinned
   up/home pair.
5. **Richness inside minimalism** — long-press peek, ambient status line,
   live value on the node (prototype before promise).
6. **Owner bets** — App mode (graph's operator face), collapse-to-node,
   spoken subgraphs (proposal-only, never auto-apply).

## Mechanics worth stealing (all scouts, deduped themes)


### TouchDesigner network editor ergonomics
- **Tab-to-create with type-ahead + Enter to place** [cost M, mobile: yes] — Tab (or double-click empty canvas) opens a searchable operator-create dialog right at the cursor. User types a fragment of the op name, list filters live, Enter places the top match and closes the dialog — no mouse trip to a menu bar at all. *Steal:* Bind a hotkey (or a persistent '+' touch target for mobile) that opens a fuzzy-search palette anchored at last-tap/cursor position; typing filters the node registry; Enter/tap-first-result places it. Keep it to one interaction, not a two-step 'open menu, then open submenu' dropdown — matches the existing wire-first, no-dropdown value.
- **Modifier-held create-and-chain (Shift = wire in series, Ctrl = stack in parallel)** [cost S, mobile: partial] — While the create dialog is open, holding Shift and picking successive ops wires each new node to the previous one's output automatically, building a chain with zero manual wire-drags. Holding Ctrl instead drops each pick as an unconnected sibling below the last. *Steal:* Add a 'chain mode' toggle in the palette (a held button, or a preceding tap on the source node) so consecutive picks auto-wire from the prior node's single output — a natural fit for the one-output-per-meaning rule since there's no ambiguity about which output to chain from.
- **Middle-click (or alt+right-click on trackpad) info overlay** [cost S, mobile: yes] — Middle-clicking any node/wire pops a diagnostic panel: cook time, resolution, sample/channel count, errors — without opening a full parameter dialog or leaving the canvas. *Steal:* Long-press (mobile) or a small 'i' affordance on hover reveals a lightweight tooltip/panel with live values, error state, and perf cost for that node — read-only, dismiss-on-release so it never competes with the wire-drag gesture.
- **Flags as single-letter toggles on the node itself (bypass, viewer-active, render, display)** [cost M, mobile: yes] — Selecting a node and pressing a single letter (b/a/r/d) toggles a binary state — bypass, viewer-active, render, display — directly, no dialog. The flags render as small persistent icons on the node's edges so state is visible at a glance across the whole network. *Steal:* Give each node a small row of tappable icon toggles on its body (not a menu) for the 2-3 states Raw actually needs (e.g. bypass/mute, 'shown in viewport'), always visible, always one-tap — matches minimalism because it's icons not text, no menu needed.
- **Right-click-on-wire → insert operator** [cost M, mobile: yes] — Right-clicking directly on an existing wire (not a node) offers 'insert operator', which splices a new node into that connection, auto-rewiring both sides. *Steal:* Make the wire itself tappable/long-press-able; offer 'insert node here' which opens the same search palette, and on pick, auto-splices into that connection preserving both existing endpoints.
- **Pane-bar network-path breadcrumb + one-key enter/exit component** [cost S, mobile: yes] — The top of every network view shows a clickable breadcrumb of the current nesting path; clicking any ancestor jumps straight there. Entering a sub-network is one click/keypress ('I') on the selected node; 'U' goes up a level; 'H' homes/fits the current network to view. *Steal:* Persistent breadcrumb bar at the top of the canvas, plus a thumb-reachable 'up a level' and 'fit/home' button pinned in a fixed corner for mobile, so zoom/pan recovery never requires a pinch gesture search.
- **Box-zoom via drag-direction (drag one way to zoom in, opposite way to zoom out)** [cost S, mobile: no] — Holding a modifier and drawing a marquee box zooms to that box; drawing the box in the reverse diagonal (right-to-left) zooms out instead, using one gesture with a directional flip rather than two separate tools. *Steal:* Less directly portable to touch (pinch-zoom already owns this niche and is more natural there) — worth flagging as a case NOT to copy onto mobile: keep pinch/double-tap-to-fit instead of a directional-drag convention.
- ANTI: Modal parameter dialogs that block the canvas: TD's own users complain the dialog can't be resized to see long expressions, has no Tab-between-fields, and hides the target op's path — don't gate an edit behind a heavy dialog when an inline/side-panel editor would keep the canvas in view. | Overloading single-letter keyboard shortcuts (a/b/r/d/u/i/h) as the primary interaction model: fast on desktop with a keyboard reachable at all times, but this whole layer is invisible and unusable on a touch-only session — any mechanic borrowed from TD needs a visible on-canvas equivalent, not just a hotkey, or one-finger mobile users get a permanently second-class tool. | Four parallel parameter modes (Constant/Expression/Export/Bind) selected per-field with no visual distinction until you dig in — this kind of quiet complexity contradicts a wire-first, few-words design: multiplying modes per field is the opposite of one-output-per-meaning simplicity. | Middle-click as the discovery path for critical diagnostic info: cook time, errors, resolution are only reachable via a mouse button most trackpads and all touchscreens lack, forcing an awkward alt+right-click workaround — don't put essential (non-optional) information behind an input method a chunk of your users don't have. | Box-zoom direction as a hidden convention (drag one way vs. the other) — clever for power users but undiscoverable and untranslatable to touch; avoid gestures whose meaning flips based on direction with no visible affordance.

### Browser/visual patcher UX mechanics for fast wiring
- **Drag-from-port-into-empty-space spawns a searchable, type-filtered node picker (Pd autopatch lineage, adopted by cables.gl, Node-RED Quick-Add, UE Blueprints)** [cost M, mobile: yes] — Start a drag from any output/input port; if you release over empty canvas instead of another port, a small searchable list opens at the release point, pre-filtered to nodes whose matching-type port faces the direction you dragged from. Picking one places the node already wired. *Steal:* On pointerup with no drop target, open the op-search overlay anchored to the release coordinate, seeded with the dragged port's type as a filter tag; committing a choice (tap/Enter) both instantiates the node at that position and completes the wire in one transaction.
- **Autopatch chaining (Pure Data Ctrl+1 lineage)** [cost S, mobile: yes] — Placing a new node from a selected node auto-connects the selected node's default output to the new node's default input, and the new node stays selected so the next placement chains again — a whole linear chain can be built by repeated 'add' taps with zero explicit wiring. *Steal:* Give the palette a persistent 'last placed node' pointer; a tap-to-place from the palette (not a drag) auto-wires from that node's primary/first output and re-arms itself as the new selection — ideal as the one-finger-tap fast path, distinct from the precision drag-wire path above.
- **Type-directed 'press a key/hold to snap into type-filtered mode' while dragging a link (vvvv gamma's '.' quick-link-by-type, gamma 6.0)** [cost M, mobile: partial] — While mid-drag on a wire, a single modifier (in gamma, the '.' key) switches the drop target list into 'By Type' view without needing a double-click detour, so the picker only shows ports/nodes whose type matches the wire in hand. *Steal:* On mobile there's no modifier key, so translate this to a long-press-then-drag: the instant the drag exceeds a small threshold, auto-narrow the drop targets to type-compatible ports/nodes and visually dim everything else on the canvas so the eye doesn't have to search either.
- **Ctrl/Cmd-click-chain wiring (Node-RED)** [cost S, mobile: yes] — Click (not drag) a node's output port, then click a target node's port; if the modifier key stays held and the node you just wired to has its own output, a new pending wire immediately starts from there, letting you click through a whole chain without ever dragging. *Steal:* On touch, replace 'modifier held' with 'tap port, then tap next port' as the default (no drag needed at all) — tap-tap-tap chains a wire path; a real click-and-drag remains available for precise single connections. This is the touch-native analogue of the desktop-only Ctrl-click trick.
- **Mid-wire insert: click the dot on a cable's midpoint to splice a new node in (cables.gl)** [cost M, mobile: yes] — An existing connection renders a small circle at its midpoint; clicking it (with one of the two connected nodes selected) opens the node picker and inserts the chosen node inline, rewiring both halves automatically. *Steal:* Render every wire with an invisible-until-hover (or always-visible-but-small on touch) midpoint handle; tapping it opens the same searchable palette used for drag-to-empty-space, and confirming splices the new node into both existing wire's endpoints.
- **Escape/global key opens the full searchable node library regardless of context (cables.gl Esc, Max 9's filterable Patcher List View)** [cost S, mobile: yes] — A single global shortcut (Esc in cables.gl) opens a full-text-searchable list of every op in the library, independent of any wire-drag context, for when the user just wants to drop a fresh unconnected node or explore what exists. *Steal:* Give Raw one global 'add' affordance — for touch, a persistent small FAB or double-tap-on-empty-canvas — that opens the same searchable palette used by the drag-to-empty-space flow, dropping an unwired node at the tap location; keep it visually identical to the wire-triggered picker so users learn one UI for both entry points.
- **Patcher List / filterable object index as a companion to the canvas (Max 9's Patcher List View)** [cost M, mobile: yes] — A side panel lists every object instance currently in the patch, filterable by text, letting you jump-select an instance on the canvas (and see live values) without visually hunting through a large or off-screen patch. *Steal:* On mobile where screen real estate is scarce, make this a slide-up sheet (not a permanent side panel): text search across node labels/types, tap a result to pan-and-center the canvas on it and briefly highlight it. Doubles as a way to avoid ever needing minimap/zoom-out gymnastics on a phone.
- **Suggested-ops-by-port-type when hovering a drag over a node's body, not just its ports (cables.gl 'drag cable to the center of an op')** [cost M, mobile: yes] — Dragging a wire and releasing over the body of an existing node (not a specific port) shows the subset of that node's ports matching the dragged wire's type; if there's exactly one match it auto-connects with no picker at all. *Steal:* Make every node's whole hit-box a valid wire-drop target, not just its ports; on drop, filter to type-compatible ports and auto-resolve when unambiguous, else show a tiny inline picker of just the 2-3 candidate ports. This is a major precision relief for touch.
- ANTI: Dropdown/context menus for node function selection (Node-RED's older node config panels, right-click 'add node' menus in generic editors) — forces a targeting+scroll+read loop; violates Raw's wire-first, one-output-per-meaning rule outright. | Modal type-mismatch dialogs (some Blueprint-style editors pop a blocking alert when you try to wire incompatible types) — kills flow, especially bad on touch where dismissing a modal is an extra full-hand gesture. | Small fixed hit-targets on ports (classic Pure Data ~4px inlet nubs) — unusable at one-finger mobile scale; needs to become an oversized invisible hit-area around the visible dot. | Separate 'connect mode' vs 'move mode' toggle (older node editors) — adds a mode switch the user must remember; direct drag-from-port-vs-drag-from-body disambiguation is strictly better and is what every modern tool converged on. | Auto-search box that steals focus/keyboard on every click-empty-space (annoyance reported in some cables.gl and UE Blueprint threads when it fires on accidental clicks) — must trigger only on a deliberate gesture (drag-release, not a bare tap) or it becomes a constant interruption on touch. | Text-typed connections/expressions instead of drawn wires (n8n's expression fields, some low-code tools) — reintroduces a keyboard-first path that breaks one-finger mobile use and the wire-first principle. | Unbounded pin/inlet lists shown by default (Max objects that expose every optional inlet) — clutters the node and multiplies mis-taps on small screens; should default to a minimal pin set with an explicit 'more' affordance (vvvv gamma's Optional-visibility model).

### Node UX at scale: Blender geometry nodes, Unreal Blueprints, Godot visual shaders
- **Drag-off-pin summons type-filtered search menu** [cost M, mobile: yes] — Drag a wire from any output (or input) pin and release on empty canvas: a search palette opens at the drop point, pre-filtered to only nodes whose matching pin type fits, with the wire auto-connecting to the first compatible pin on the node you pick. This is Unreal Blueprint's 'context sensitive' action menu. *Steal:* On drag-release-in-empty-space, open the existing searchable op palette anchored to the release point, pre-filtered by the dragged pin's data type (number/signal/geometry/MIDI/video), with the palette's top result wired in on Enter/tap. This is close to Raw's existing wire-first philosophy — it just adds the 'search opens already filtered and already positioned' step.
- **Fuzzy text search as default add-flow, not a browse tree** [cost S, mobile: yes] — Blender's Node Wrangler: press Shift+A then immediately S to jump straight to a text search box over the node menu, instead of clicking through category submenus. *Steal:* Make the op palette open with the search field already focused and keyboard/on-screen-keyboard up — no intermediate category screen at all. Fuzzy-match on name + common synonyms (e.g. 'noise' also matches 'random').
- **Reroute dots as invisible wire-bending, inserted by dragging onto a wire** [cost S, mobile: partial] — Blender: Shift+RMB-drag across a noodle drops a reroute point on it, letting you bend a wire around clutter without creating a real node. Godot/Blueprint have similar 'knot' nodes. *Steal:* Let a tap-and-drag on an existing wire (not a pin) spawn a draggable waypoint on that wire; store it as a bend-point in the wire's geometry, not a graph node, so it never shows up in search/palette and can't be a source of a bug. On mobile, a small always-visible handle mid-wire (rather than requiring a modifier-drag) makes it discoverable without a keyboard modifier.
- **Frame/group selected nodes with one shortcut, frame drags children together** [cost M, mobile: partial] — Godot proposal / common pattern (also Blender's Ctrl+G, Unreal's comment boxes): select nodes, press one key (Cmd/Ctrl+J or +G) to enclose them in a named, resizable frame; moving the frame moves everything inside it; the frame's label doubles as a comment. *Steal:* Selection (tap-multi-select or lasso) + a toolbar/context action 'Frame' draws a labelled rounded rect behind the selected nodes; dragging the frame's title bar drags all contained nodes; tapping the label opens a single-line text edit. Keep it purely visual/organizational — no execution semantics — so it's safe to add without touching the graph engine.
- **Collapse node to icon / collapse subgraph to single node** [cost L, mobile: yes] — Blueprint's 'Collapse to Function' and 'Collapse Nodes' turn a selected cluster into one visually compact node with the same external pins; Blender nodes have a collapse toggle that hides all internal sockets down to a single dot per side. *Steal:* Give every node a collapse toggle that shrinks it to a title-only pill with merged in/out connection points (multiple wires converge on one dot); for a selected cluster, offer 'group into subgraph' that produces one node with promoted ports — this doubles as the mechanism for user-defined reusable ops, valuable for theatre-makers repeating a rig across scenes.
- **Type-colored pins/wires as the only 'legend' needed** [cost S, mobile: yes] — All three tools color-code sockets and wires by data type (exec white, float green/grey, vector yellow, bool red in Blueprint; geometry/vector/shader colors in Blender) so you can read compatibility at a glance without opening anything. *Steal:* Assign Raw's existing data kinds (number/signal/geometry/MIDI/video) a fixed hue each, apply it to the pin dot, the wire stroke, and a thin edge on the node body for its primary type — keep the dark palette quiet by making color show up only on pins/wires, not as background fills.
- **Keep-context-menu-anchored search filtered by direction and connected pin, with an escape hatch to unfiltered browse** [cost S, mobile: yes] — Unreal's right-click / drag-off menu shows only contextually valid actions by default but has a visible 'Context Sensitive' toggle to see the full unfiltered list — so power users aren't ever trapped by an overly aggressive filter. *Steal:* Default the palette to type-filtered results but always show a one-tap 'show all' toggle at the top of the search results, remembering the user's last choice per session so it doesn't nag repeat offenders.
- **Live value/preview inline on the node (Blender node compositor viewer, Blueprint pin watch tooltips)** [cost L, mobile: yes] — Nodes can show a small live thumbnail (Blender: a shader ball or image thumbnail baked into the node when 'viewer' is attached) or a live value readout right on the pin (Blueprint: hover a pin during PIE to see current value; Node Wrangler has a 'Viewer Node' shortcut Ctrl+Shift+click to instantly preview any node's output). *Steal:* Ctrl/long-press-click on any output pin sets it as the 'watched' output, showing a tiny live number/sparkline/thumbnail badge on that pin persistently until cleared; for geometry/video outputs show a tiny live-updating thumbnail. This is a natural extension of Raw's live-data philosophy and probably the biggest UX lever available.
- ANTI: Deep hierarchical add-node menus (category > subcategory > sub-subcategory) — Blender's own default Shift+A tree is the thing Node Wrangler's search exists to bypass; don't ship a browsing menu as the primary path when a flat fuzzy search is one keystroke away. | Dropdown-based node configuration (mode selects, type pickers baked into the node body) — this is exactly what Raw already rejects, but it's worth naming because Blueprint and Shader nodes lean on it heavily (e.g. Lerp node's Alpha type dropdown) and it's tempting to copy verbatim; wire-first means a second input pin, not a dropdown. | Auto-inserted conversion/cast nodes that silently appear on connection (Blueprint does this for some pin mismatches) — great for power users, disorienting on a small screen where the inserted node crowds the view and the user didn't ask for it; if adopted, must be undo-one-step and visually obvious, never silent. | Marquee/box-select as the only multi-select method — fine with a mouse, painful with one finger where a drag is already claimed by pan or wire-draw; any 'select multiple then Ctrl+G to frame' workflow needs a tap-to-multi-select alternative or it's desktop-only in practice. | Comment/frame text that requires a double-click-to-edit inline text field with no visible affordance — discoverable on desktop by habit, invisible on touch; frame/group labels need a visible edit tap-target, not a hover-cursor hint. | Right-click-to-summon as the ONLY entry point for the add/search menu — no right-click on touch; needs a persistent tap target (e.g. a always-visible + button or double-tap-canvas) or it's unreachable one-fingered.

### Touch-first node/canvas tools
- **Tap-tap connect (no drag-a-wire)** [cost M, mobile: yes] — Instead of dragging a wire from an output pin to an input pin, tap the source pin once, then tap the destination pin. React Flow's touch mode implements exactly this: 'connect nodes on a touch device by tapping two handles in a row,' with handle hitboxes enlarged specifically for touch. *Steal:* In Raw, tapping an output port arms it (glow/pulse), then tapping any compatible input port on any node completes the wire and clears the arm state; tapping empty canvas or the same port again cancels. Keep drag-wire for mouse/pen but make tap-tap the primary path on touch, detected via pointer type not screen width (Pencil-equipped iPads still want drag).
- **Enlarged, forgiving hit targets on ports** [cost S, mobile: yes] — Touch hitboxes for connection handles are made larger than their visual dot — React Flow explicitly grows the tappable area independent of the rendered size when in touch mode. *Steal:* Give every port a visually small dot but a >=44px invisible tap zone, expanding when ports are far apart and only requiring a secondary confirm tap when two ports' hit zones would overlap.
- **Hold-canvas-with-one-finger to arm multi-select (no modifier keys)** [cost M, mobile: yes] — React Flow's touch pattern: hold empty canvas with one finger to arm 'selection mode,' then tap nodes/edges to add them to selection; holding and dragging instead does rubber-band select. *Steal:* Long-press (~300-500ms) on empty canvas opens select-mode with a persistent thumb-reach action bar pinned at the bottom ('N selected — wire together / delete / group'), substituting for the modifier key Raw can't have on mobile. A quick tap on canvas always just deselects.
- **Popover/palette spawns at the touch point, not docked to an edge** [cost M, mobile: yes] — Touch-first tools surface node-creation and quick-action menus centered exactly where the finger landed rather than in a sidebar or dropdown elsewhere on screen. *Steal:* Long-press or double-tap empty canvas opens the searchable op palette (matching Raw's existing desktop Tab pattern) anchored at the touch point, clamped to stay within thumb arc and on-screen near edges; placing an op auto-wires to the last-armed port in one continuous gesture.
- **Fixed finger-count-to-meaning mapping for canvas gestures** [cost S, mobile: yes] — Across Procreate, FigJam, and tldraw, one finger is reserved for content manipulation (draw/select/move/connect) while two fingers are always and only pan+pinch-zoom — the mapping never inverts by mode. *Steal:* Lock 1-finger drag = move node/draw wire, 2-finger drag = pan, pinch = zoom, with zero exceptions across modes — a second finger touching down mid-wire-draw hands off to pan without cancelling the in-progress wire.
- **Bottom sheet for node inspector instead of an inline floating panel** [cost M, mobile: yes] — Mobile-adapted canvas tools present a selected object's properties in a sheet sliding up from the bottom edge — thumb-reachable, dismissed by swipe-down or tapping canvas — rather than a popover anchored to the node itself. *Steal:* Selecting a node in a touch session opens a compact bottom sheet with its few live values (Raw's wire-first ethos keeps this minimal — a value scrubber, delete/duplicate row), never a floating box the thumb could cover.
- **Two-finger double-tap to zoom-to-fit** [cost S, mobile: yes] — Standard across FigJam/tldraw/Procreate: pinch-zoom carries inertia, and a two-finger double-tap snaps back to fit-all or fit-selection. *Steal:* Add two-finger double-tap = zoom-to-fit-selection (fit-all if nothing selected) as a standing Raw canvas gesture, independent of any toolbar button.
- **Auto-wire from an armed port when placing a new node** [cost M, mobile: yes] — If a port is already armed via tap-tap-connect and the user instead opens the add-node palette, placing the new op auto-connects the armed port to that op's best-matching first input. *Steal:* Wire the armed-port state (from mechanic #1) into the add-node palette's placement handler so drop = connect automatically, with the wire visibly previewed as the palette is still open so the user can cancel by tapping elsewhere.
- **One-finger-reachable undo (not two/three-finger, not a menu)** [cost S, mobile: partial] — Procreate binds undo/redo to two/three-finger taps by default but ships a documented single-touch companion mode specifically for accessibility, keeping the correction gesture always available regardless of hand mobility. *Steal:* Put a small fixed-position undo affordance (corner button, not a menu) reachable by one thumb at all times in Raw's touch UI — skip two/three-finger taps as the primary path since they violate one-finger-only.
- ANTI: Drag-a-wire as the ONLY connection method on touch — the fingertip occludes the exact target pixel it needs to hit, causing high mis-drop rates; always offer tap-tap as the primary touch path, not merely an alternative. | Hover-dependent affordances (tooltips, hover-reveal ports, cursor-following previews) — touch has no hover state, so anything only visible/usable on mouse-hover is invisible and undiscoverable on a phone. | Fixed-position sidebars/toolbars docked at a screen edge far from the point of action — forces the thumb to travel across a 6-inch screen and covers content mid-reach; prefer point-of-touch popovers or bottom sheets. | Small hit targets sized to match visual size (an 8px port dot with an 8px hitbox) — fails immediately under a fingertip; always decouple visual size from touch hit size. | Context-dependent gesture meaning (one-finger drag pans in this mode but draws a wire in that mode) — breaks the single learnable mapping and causes confident wrong actions since there's no hover-preview to catch it beforehand. | Modifier-key-gated actions (shift-click multi-select, ctrl-drag duplicate, alt-drag disconnect) ported unchanged to touch with no substitute gesture — completely inaccessible with no keyboard present. | Two-simultaneous-independent-touch-point gestures (one finger holding a node steady while another drags a wire from it) — workable on a large tablet, unreliable on a 6-inch phone where both fingers crowd the same small area. | Long-press durations copied from desktop-derived defaults without testing on a real device — too short triggers accidental selection-mode during ordinary taps; too long feels unresponsive. Must be tuned on an actual phone.

### Rich-but-minimal UI density: making empty space work (Linear, Arc, iA Writer, Teenage Engineering, Berlin-school audio UIs, Japanese information design)
- **Shift-layer reveal (OP-1/OP-Z secondary function row)** [cost M, mobile: yes] — A single held modifier key (shift) swaps every knob/button's meaning to a secondary function, shown live on a second row of the display or via a color-LED state change on the control itself — not printed on the hardware. Release shift, everything reverts instantly. *Steal:* On a node, a single held gesture (long-press, or a thumb-modifier like a corner 'alt' zone) swaps the node's visible ports/values to a secondary set — e.g. hold to see raw values instead of smoothed, or see min/max instead of current. Render the alt-state as a genuine label change on the node face, never a static second row that's always there.
- **Press-and-hold live preview with snap-back (OP-Z temporary parameter tweak)** [cost M, mobile: yes] — Holding shift + turning a dial temporarily overrides a parameter for as long as it's held; releasing reverts to the prior value. The change is auditioned live, not committed until you choose to keep it. *Steal:* A press-hold-drag on a numeric input previews the new value live in the 3D scene; releasing at the current position reverts, dragging past a threshold (or releasing over a 'commit' zone) locks it in. No dialog, no undo needed for the common case.
- **Peek window instead of full navigation (Arc Peek)** [cost M, mobile: yes] — Clicking a link/reference opens a small floating preview window on top of the current context rather than replacing the view or opening a new full tab/page. *Steal:* Tapping a node's upstream/downstream reference (e.g. 'this feeds 3 other nodes') opens a small floating peek card showing those nodes in miniature, without leaving the current pan/zoom position on the graph. Dismiss by tapping outside.
- **Hover-to-expand sidebar/dock with persistent collapsed state (Arc 48px→240px)** [cost M, mobile: partial] — An edge dock sits collapsed at a minimal width showing only icons/glyphs; hovering (or, for touch, tapping the edge) expands it to full labeled width with a brief delay so accidental brushes don't trigger it, and it collapses again on focus-away. *Steal:* A node/op library dock lives collapsed as a thin icon rail on one edge of the canvas; tap (mobile) or hover (desktop) expands it to full search+label width, tap elsewhere collapses it. The graph canvas itself never shrinks permanently to make room.
- **Status line as ambient truth (Linear's inline banner / DAW transport bars)** [cost S, mobile: yes] — A single persistent thin strip (top or bottom) shows only what's true right now — selection count, current BPM/frame, connection state, last-saved time — in plain small type, updating live, with no chrome around it. *Steal:* A one-line status bar at the bottom of the Raw canvas shows: selected node's live output value, frame rate, MIDI/OSC connection dot, and nothing else — updates every frame, never opens on click, just reads. Typography does the work (monospace, muted color, tabular numbers so it doesn't jitter).
- **Delayed keyboard-shortcut hint banner (Linear's cursor-pause nudge)** [cost S, mobile: yes] — After the pointer/focus rests on an interactive element for ~1-2 seconds without action, a small unobtrusive hint appears showing the faster keyboard/gesture path for that same action, then fades if unused. *Steal:* When a user drags to draw a wire slowly or hesitates over a node for 1.5s, a tiny hint appears near their thumb: 'or: tap output then tap input' or 'long-press to duplicate' — teaching the fast path exactly at the moment of friction, then disappearing.
- **Content-as-chrome typography (iA Writer: fonts and spacing ARE the interface)** [cost S, mobile: yes] — Instead of boxes, borders, and icon buttons to organize the screen, differences in weight, size, monospacing, and color alone signal what's a label vs. a value vs. an editable field vs. a state — visual hierarchy comes from type, not containers. *Steal:* On a node: node name in one weight/size, live value in a distinct monospace/tabular-figure style with a different color, port labels in a smaller muted weight — no boxes drawn around each field, just type contrast doing the separation. Saves the pixel-budget boxes would cost, which matters at one-finger mobile scale.
- **Anchored dense parameter grid (Octatrack's 2-row knob-to-label spatial mapping)** [cost M, mobile: yes] — Six on-screen parameter slots are laid out in the exact same physical grid position as the six hardware knobs below the screen (2 rows of 3), so knob position always matches label position 1:1 regardless of which parameter page is active. *Steal:* When a node exposes several editable parameters, render them in a fixed grid position keyed to their physical order (top-left is always parameter 1) even as which parameters are shown changes by node type — so a user's thumb learns 'top-left is the primary value' as a universal habit across the whole app.
- **Information-dense-but-breathing signage (Japanese wayfinding: generous whitespace around high info-density)** [cost L, mobile: yes] — A single sign carries far more information than a Western-minimalist equivalent (platform, direction, transfer lines, next-train timing) but stays legible because every element gets generous surrounding whitespace and a strict typographic scale, rather than being cut for sparseness. *Steal:* Let a node show more at rest than the current Raw default IF each piece (name, live value, connection state) gets its own clear whitespace margin and consistent type scale — resist the urge to hide information into taps purely for 'minimalism's sake' when it could instead be shown calmly.
- ANTI: Hover-only disclosure with no persistent trigger: if a critical control (a node's second output, a parameter's alt value) exists ONLY on :hover, it doesn't exist on touch. ### Node-based creative tools, 2025-2026: what's moving in browser/AI patching and TouchDesigner alternatives, for di.iiii Raw
- **Graph mode vs. App mode split (ComfyUI 'App Mode')** [cost M, mobile: yes - the App/run view is the one that should be the one-finger-mobile default] — The same node graph has two views: a build/patch view showing every node and wire, and a run/perform view that auto-generates a clean form (sliders, buttons, a few labeled controls) from just the exposed inputs — no wires visible, no node count visible. *Steal:* Any node can be flagged 'exposed'. A second top-level tab/route renders only exposed nodes as plain controls in DOM order, live-bound to the same graph state. Raw's show-mode (if it has one) should generate from this flag rather than needing a second manually-built UI.
- **Wire-follows-placement (Krea Nodes sequential drop)** [cost M, mobile: yes - this is the single highest-leverage mechanic for one-finger use] — When you drop a new node from the palette, it auto-wires from the previously-selected node's matching output into the new node's first compatible input — you don't drag a cable for the common 'next step in the chain' case, only for branches/merges. *Steal:* On node-create-via-palette (see Tab-search below), auto-connect from the last-touched node's first output to the new node's first input of matching type; show the wire as already drawn, selected, and immediately re-draggable if wrong.
- **Type-filtered Tab/search palette at cursor (Blender Node Wrangler / UE Blueprint lineage, still the baseline in 2026 tools)** [cost M, mobile: partial - long-press-and-drag-to-empty-space is a known one-finger gesture] — A key or long-press opens a searchable node list positioned at the touch/cursor point; if it was invoked by dragging off an existing output, the list is pre-filtered to only nodes with a compatible input of that type, and Enter/tap places + wires it in one step. *Steal:* Drag from an output onto empty canvas -> palette opens pre-filtered by that output's type; matches the CLAUDE.md mandate of 'no dropdown menus on nodes, one output per meaning' by moving the decision into the search step instead of a per-node dropdown.
- **Reroute/bundle nodes + link render modes to fight 'spaghetti wires'** [cost S, mobile: yes - pure rendering change] — Dedicated invisible reroute points let a wire bend around clutter without adding a real op; a global toggle switches wire rendering between full bezier curves, straight lines, or bundled/minimized rendering that collapses parallel wires into a single visual channel between the same two clusters. *Steal:* Ship a per-space 'tidy wires' toggle (bundle same-route wires, auto-curve away from node bodies) rather than requiring users to manually drag reroute dots for basic legibility; save the toggle state per space like any other view preference.
- **Typed, color-coded sockets as the only 'menu' on a node (industry-wide convergence: Houdini/UE/Krea multimodal all do this)** [cost S, mobile: yes - this is what makes small] — Every socket's color encodes its data type (number, signal, geometry, MIDI, video...) consistently across the whole app; a node exposes only sockets, never a dropdown of modes — switching behavior means picking a different node from the palette, not reconfiguring one node. *Steal:* Lock a fixed color per data type in the design tokens now (not per-node, not themeable) so the palette becomes muscle memory across the whole node library; the Tab-search palette (above) should also color its list entries by type for the same reason.
- **Natural-language subgraph generation, kept as a proposal you accept/edit (Krea 'Node Agent')** [cost L, mobile: partial - typing a prompt is fine one-handed] — A prompt box generates a candidate chain of nodes + wires onto the canvas as a normal, editable subgraph — not a black-box result — which the user then rewires or deletes nodes from like anything else they built by hand. *Steal:* If/when Raw adds an AI assist, have it emit real nodes onto the canvas (using the same palette + auto-wire mechanic above) rather than a separate opaque 'AI block' - so the output is inspectable, deletable, and rewireable with zero new UI vocabulary.
- ANTI: Desktop-only editing with mobile treated as 'runs fine, edit on a laptop' (cables.gl's own docs hedge that tablet/phone editing is unsupported/unexpected) - for a tool with one-finger mobile as a first-class goal, this is the exact posture to avoid; touch must be a primary input model from day one, not a degraded fallback of mouse interaction. | Nodes that each expose many parameters via dropdowns/multi-field bodies (ComfyUI's base node set is the widely-mocked example: a basic text-to-image chain needs ~7 nodes each with several settings) - this is precisely the 'dropdown menus on nodes' pattern di.iiii's brief already rules out, and it's the direct cause of the graphs people complain are unreadable. | Letting the canvas grow unbounded with no legibility discipline (no auto-tidy, no bundling, no minimap/zoom-to-fit shortcut) until the graph is an unreadable mass of crossing wires - the 'spaghetti wires' failure is a 2026-wide, well-documented complaint against the market leader and is cheap to prevent early with rendering-level fixes rather than expensive to fix later by asking users to manually reroute. | AI-generated graphs presented as opaque results rather than editable node structures - the field is visibly correcting away from black-box 'prompt and pray' generation back toward inspectable, rewireable chains; building an opaque AI feature now would be adopting a pattern the market is already leaving.
