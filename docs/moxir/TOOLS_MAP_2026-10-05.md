# MOXIR — the tools map, the diagnosis, and one rebuild (2026-10-05)

Owner, 2026-10-05: *"in moxir it's messed — analyze tools and things and let's rebuild that part."*

MOXIR is the techno night of **17 Oct 2026** in the Charentsavan factory hall (the **place**). Its twin in
di.iiii is the **space** `moxir`. Each rig version is one **project** in that space. The 3D hall you walk in
is the **scene**. **Light** is the lighting desk at `/light/` on a local install.

This is a READ-ONLY analysis. Nothing was built, run against a server with writes, tested or linted.
Every claim carries a tag:

- **CONFIRMED** — I saw the value (file:line, PR, or a read-only GET on 2026-10-05, about 04:00–05:00 +04).
- **SUSPECTED** — inferred, or the deciding fact was out of reach.

Code read at origin/dev `b3d7f76b`. Data read from `local.thedi.studio` and `dev.diiii.xyz` (GETs only;
`/light/api/clock` only, never `/light/api/show`). Builds on the deep audit on branch
`docs/moxir-audit-2026-10-05` (areas A–D, cited as A-nn, B-n, C-n, D-n).

---

## 0. The short version

1. **Too many writers, no single direction.** A version project is changed by ~20 scripts and 5 browser
   tools, in place, in an order nobody wrote down in one file. Git is one input among many, not the source.
2. **The same fact lives in 3–9 places**, and they disagree today (fixtures, addresses, cues, picture, hall).
3. **What is on Light is not what was chosen.** Light runs Minimal's loop with 241 lamps of 7 other versions;
   the chosen version, Known · full, is not on it at all.

**The proposal, in one line:** one git file per fact, one build command that turns git into the show project
(as ops, with a diff first), and everything else (Light, the patch sheet, the equipment list, the prices) is
read from that build — never edited beside it.

## 4. The rebuild — one shape

### 4.1 The rule

**Git holds the design. One build command makes the show project from git. Everything else reads that
project. Nothing edits beside it.** This is the asset-publish model the 10-04 decision already cites
(ShotGrid published files, USD's resolver): a version is made by a recorded build from pinned inputs, and one
pointer says which version is approved.

### 4.2 One source per fact

| fact | the one source | derived from it (never edited) |
|---|---|---|
| fixtures, positions, aims, looks, cues | `scripts/place/rigs/moxir-versions-2026-10-17.json` → generated `moxir-2026-10-17-known-full.json` + `.show.json` | project document, Light's looks and cues, scene deck view |
| DMX address and mode | `moxir-2026-10-17-known-full.patch.json` (from #766) + `fixtures.json` channel lists | document addresses, Light's patch, patch sheet, MVR |
| picture | a `picture` block in the rig file (night, fog, **exposure**, haze) — moves 3.5 from `realism.mjs:179` into code | the project's world and render settings |
| hall | dims + features JSON in git, and the built GLB **pinned by sha256** (df837baa for 17 Oct) | the scene's hall in the project |
| what we take, vendor, prices | di-atlas `production/source-list-moxir-2026-10-17.csv` (private) | equipment page shows counts; prices stay private |
| which version is for the show | the version list's `for-the-show` entry with `madeFrom` + rig blob + commit | `publishedProjectId`, which project goes on Light |

A **show lock** file (`scripts/production/locks/moxir-2026-10-17.json`, new) names the rig file blob, the
patch plan blob, the hall GLB sha256 and the code commit. The build refuses to run if any of them differs.

### 4.3 One build command (new; wraps tools that already exist)

```
node scripts/production/build-show.mjs --production moxir-2026-10-17 --version known-full --api <dev> --dry-run
```

1. Builds the project offline from git (the same pure steps #767's `rebuild-compare.mjs` already replays:
   versions report, pieces, venue plan, looks, patch plan, picture).
2. Compares it with the live `moxir-hall-known-full`, entity by entity, and **prints the diff**.
3. Without `--dry-run`: writes only the diff, as ops (so `di follow` carries it; no whole-document PUT),
   reads back, records the new fingerprint, commit and `madeFrom` in the version list.
4. Then `desk-plan.mjs` (#766) puts that same project on Light, exact or fail, OUTPUT untouched; then
   `show-clock.mjs` sets `showEpoch`; then `patch-sheet.mjs --pdf` prints the crew sheet.

The project id stays `moxir-hall-known-full`, so the front door, the follow and the list keep working.
A browser edit that is not in git shows up in step 2 as a diff: either it goes into the rig file, or the
build removes it. That is the one direction. (SUSPECTED effort: 1–2 days, because the replay and compare
exist in #767; the diff-to-ops writer is new.)
