Build order that comes out of it

  1. Machines know each other, in any version.

    Protocol 1: the frozen core (hello, card, cue, blackout, picture) plus the feature hello, the machine card, finding each other on the network, both-way links, and the compatibility grid in CI. Everything after this is a feature on top, so it has to come first.

  2. Land the picture work.

    Merge #447, then #450 and #451, and rehearse you + Emilya for real. 10 cases play pictures.

  3. Jam rules.

    Holding, presence in Raw, the local certificate so phones get camera and mic. The two-artist jam is fully covered after this.

  4. Show mode.

    Pre-flight, caller, lock, snapshot, blackout from anyone (10 cases), handover, and a show-wide cue list with GO.

  5. Weak machines and appliances.

    Stage and Hands parts, boot into the job, restart, health from afar. Puts the kiosk work done by hand on asuz today into the product.

  6. More devices.

    OSC made real, the robot merged, projector control, sound-reactive nodes in the patch.

  7. Big groups and distance.

    Lanes and turns for workshops and crowds; a jam between two cities.

01 · picked: the mesh, with two modes

Jam mode and show mode

Same machines, same connections. The mode only changes who may call a cue and what's allowed to change. It's the difference between a rehearsal room and a running show.

Everyone plays

cuesany machine → any machine. Every cue shows who sent it; the last one wins

02 · how they connect

Two ways in: run it or speak to it

A machine that runs di.iiii joins the mesh itself, so it works on any wifi with no address to type. A device that keeps its own software is reached by a driver node, on whichever di.iiii it is plugged into, that speaks its language. Nothing gets installed on that device.

04 · control

Cues, not remote control

No machine logs into another. A machine sends a cue by name, and the receiver runs it only if the cue is on its own short list and the mode allows the sender (jam: anyone · show: the caller, plus blackout from anyone). It's a lighting desk sending "go", not someone reaching into the dimmer.

partcues it acceptswhat it refuses
STAGEshow page · blackout · screens: projector / both · volume · mic on/off · reloadanything else: no shell, no installs, no file edits
HANDSpin on/off · sound route · serial send · reloadsame
SPEAKSwhatever its driver exposes: drive, lamps, DMX valuesarming and safety: those stay a human switch on the device
EVERY MACHINEoffer an update · jam/show · handover · send healthupdates during show · cues from anyone but the caller during show (except blackout)
05 · versions · every one works with every other

Any version meets any version

No one has to be on the same release. When two machines meet they agree on what they have in common, the way two musicians find a key they both know.

the core · frozen forever

Five things every release speaks the same way

hello"I am here, release X, protocol 1"
cardpart, ports, health, what it shows
cuerun a cue by name
blackoutalways, from anyone
picturereceive a picture (H.264, which everything can play)

Never renamed, never removed. This is the promise that makes every version work with every other.

extras · agreed per pair

Everything else is a feature, checked on hello

An older stage box still shows the picture, even if it doesn't have the VJ deck.

  1. Machines ignore what they don't understand, and never delete it.

    A patch from a newer version opens on an older one with the new nodes as grey placeholders ("made in a newer di.iiii"). Saving keeps them untouched, so going back to the newer machine loses nothing.

  2. Documents move forward, never backwards by force.

    A newer machine reads every older format. An older machine keeps what it can't read. Nothing gets rewritten into a shape the other side can't open.

  3. Pre-flight checks features, not numbers.

    "Can every machine in the show do what the show uses?" If asuz only shows the result, it doesn't need the VJ deck.

  4. Updating is an offer, never a condition.

    In jam, a machine with a newer release offers it and you can say no; in show, nothing updates. Being behind is never a reason to be locked out.

  5. Speaking devices negotiate in their driver.

    Each driver states which firmware or ROS versions it knows; an unknown one connects read-only and says so.

  6. Tested as a grid, every release.

    Each new release is played automatically against the older releases (hello, cue, blackout, picture, a patch opened back and forth). A red square in the grid blocks the release.

  7. Where it starts.

    From the first release with protocol 1, every version works with every other. Today's 0.4 installs update once; there is no adapter for them.
