Door 1

Use di.iiii

Needs only a terminal and curl.

  1. Install (goes into ~/.di).

    curl -fsSL https://diiii.xyz/get | sh
    walked on r-di

  2. Open a NEW terminal so di is on your PATH, then check.

    di --version
    walked on r-di

  3. Start it. It opens http://diiii.localhost/ (if port 80 is taken it prints another address).

    di up
    walked on r-di

  4. Make a space, then save it as one file.

    di new my-space di save my-space
    walked on r-di
Says "port 4000 is held by another program"?Something else uses that port. Run di up --port 4171 and add --port 4171 to di new, di save, di status and di down. No screen? add --no-open.

Door 2

Work on the code

Needs git and Node 22 or 24 with npm 10+. The clone is ~490 MB.

  1. Get the code.

    git clone https://github.com/dob-0/di.iiii cd di.iiii
    walked · 87 s

  2. Install the app and the server. Also switches the git hooks on.

    npm ci npm --prefix serverXR ci
    walked · 19 s + 2 s on di-work (3 min on a Pi)

  3. Check the machine, before you start and before every push.

    npm run start-check
    walked

  4. Start your own branch. Never commit on dev or main.

    git switch -c feat/<what>-<date>
    not walked

  5. See it. Frontend 5173, backend 4000.

    npm run dev
    not walked

  6. Before you push. Lint ~2 min, tests ~19 min on a 4-core laptop.

    npm run lint && npm run test -- --run
    walked on di-work · all pass

  7. Push. A PR to dev opens by itself (needs push rights, or use a fork).

    git push -u origin HEAD
    not walked

Door 4

Sign in — admin on a new PC

Do door 1 first. Do this once per machine; no password is typed in the terminal.

  1. Ask for a sign-in. The terminal shows a short code and opens the browser.

    di login
    not walked on a new PC

  2. In the browser, sign in as yourself (GitHub, Google or Telegram), open the page it shows, and type the code.

    needs you

  3. Check. It names you, this machine, and when the sign-in ends.

    di whoami
    walked on aylmo

  4. Admin work stays in the browser: Admin page on dev.diiii.xyz/admin.

    not walked
What the terminal can and cannot doIt can read and edit your spaces and projects. It cannot publish or delete a space, or change who owns or edits one. Those stay in the browser.
How long it lastsUntil you end it (di logout, or the list at /device), or 90 days unused (a year at most). It signs in to dev.diiii.xyz by default; for another of ours add --tier prod or --tier local.

Another di.iiii: di login --to https://example.org · end it: di logout

Three ways of working, switch any time: browser only (dev.diiii.xyz) · install, no login · install + di login then di connect (every space follows, the machine stays connected). Back to no login: di disconnect, your work stays. Details: docs/START-HERE.md.

walked = run on a bare Raspberry Pi, Debian 13, Node 24, 2026-11-18 not walked = from the repo's own docs, not run yet not walked at all: macOS, Windows
