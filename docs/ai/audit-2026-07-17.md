# Full Project Audit — 2026-07-17

Method: eight independent parallel reads — six "doc-blind" ground-truth passes over
serverXR, the shared schema/node-graph layer, `src/project/`, Studio, Beta, and
infra/deploy (each explicitly instructed to ignore AGENTS.md/CLAUDE.md/docs and
reason only from source), plus two doc-claim extraction passes over every `.md`
file in the repo. The two sides were then cross-checked against each other and,
where a claim was checkable, against the live code.

This complements the 2026-07-16 six-phase audit (`known-fixes.md`, findings #1-28)
rather than replacing it — this pass is about **documentation accuracy** as much
as code correctness.

## Confirmed documentation problems

### Broken references

1. **`docs/architecture/RECURSIVE_NODE_CORE.md` does not exist**, despite being
   linked from `AGENTS.md`, `README.md`, and `ORIENTATION_MAP.md` as the
   canonical node-model doc. Fixed by writing the file for real (see below),
   sourced from this audit's own ground-truth read of `nodeRegistry.js` /
   `nodeGraphRuntime.js`.
2. **`docs/studio-beta-fork-map.md` (2026-07-16) lists `OpCreateDialog.jsx`
   as a live Beta-only file.** Confirmed via direct filesystem search: the file
   does not exist anywhere in `src/` — only a stale Vitest cache entry
   references it. `docs/ai/audit-2026-07-07.md`'s "removed as dead code" claim
   is the correct one; the newer fork-map doc regressed on this specific point.

### Stale role cards

3. **`docs/ai/roles/backend-api-engineer.md`** described a `better-sqlite3`-style
   API (`new Database()`, `.pragma()`, a `DB_PATH` env var). The actual code uses
   `node:sqlite`'s `DatabaseSync` with a hand-rolled `.pragma`/`.transaction`
   compat shim in `db.js` — `docs/ai/golden_rules.md` itself documents this
   choice and why (`better-sqlite3` has no Node 24 prebuilt / cPanel toolchain;
   `node-sqlite3-wasm` OOMs under CloudLinux LVE caps). The role card was simply
   wrong about its own project's storage engine.
4. **`docs/ai/roles/schema-protocol-engineer.md`** said asset IDs still use
   `crypto.randomUUID()`, with SHA-256 content-addressing as a future direction.
   Confirmed shipped: SHA-256-shaped asset IDs are hash-verified against actual
   file content server-side right now (`spaceRoutes.js`/`projectRoutes.js`).
5. **`docs/ai/roles/viewport-3d-engineer.md`** scopes itself entirely to
   `BetaViewport.jsx`, with no mention of Studio's own viewport at all. Studio's
   `StudioViewport.jsx` is a completely independent R3F renderer (own camera
   controls, own gizmo, doesn't reuse Beta) — the role card is incomplete for
   whoever owns Studio's 3D rendering.

### Internally contradicted docs

   "square — border-radius: 0 everywhere, never add rounding." Checked directly

   pinning test counts because they've gone stale before (the audit-2026-07-07

   for ~6 sessions) — and then two other canonical docs pinned one anyway.
8. **`docs/checkpoints/2026-04-09.md`** has a header note admitting it's stale
   (no `staging` branch exists anymore — branch flow is `dev → main`), but its
   body still walks through a full `dev → staging → main` promotion flow. A doc
   that corrects itself in one line and contradicts that correction for the
   rest of the page.
9. **Ollama model-tag drift, three ways.** `docs/ai/roles/ollama-agent.md`

   (`qwen2.5-coder:7b`, `qwen2.5:7b`, `dob-fast`, `dob-deep`, etc.) — the same

10. **`docs/roadmaps/PROJECT_DEVELOPMENT_FRAMEWORK.md`** listed `App.jsx`,

11. **`docs/architecture/PROJECT_AUDIT_2026-04-17.md`** gives specific line

### Stale feature-completeness claims

12. **`CURRENT.md` said Studio ships "five windows."** It's actually six desktop
    panels (`StudioControlCluster.jsx`: Create, Scene, World, Share, Code,

13. **`docs/SHORTCUTS.md`** describes a "Main app editor" (`/<space>`,

## Code findings (not documentation issues, found incidentally during the ground-truth reads)

Ranked roughly by real-world impact:

- **`sync pull` desyncs the version counter** (`serverXR/src/routes/syncRoutes.js`).
  After pulling a remote scene, the new version is computed from the *remote*
  scene's own embedded version field, not `localVersion + 1` — and the pull
  writes no op-log entry and broadcasts no SSE event. Connected clients
  silently stop seeing the pulled scene live and can hit spurious version
  mismatches afterward.
- **Session-cookie role/scope revocation isn't enforced per-request.** A signed
  session cookie is trusted as-is on every gated route; a DB-side role or scope
  change only takes effect when the client next hits `GET /api/auth/session` or
  the cookie's 12h TTL expires. Sync-keys, in the same codebase, check
  revocation live on every request — the same system enforces revocation
  inconsistently depending on which credential type is in play.
- **`NODE_ENV`-gated auth default.** `requireAuth` and `cookieSecure` both
  default to off unless `NODE_ENV === 'production'` exactly. A production
  deploy with that env var merely unset (not misconfigured — just absent) runs
  fully open with non-secure cookies, with nothing surfacing the fact.
- **Two independent write-lock systems for space content.**
  `spaceRoutes.js`'s `withSpaceOpsLock` and `inscriptionRoutes.js`'s own
  separate module-level lock map don't coordinate — a normal op-write and an
  inscription-write to the same space race outside each other's mutex. Caught
  after the fact by a UNIQUE DB constraint (→ 500, not silent data loss), but
  still uncoordinated.
- **`universe.node0` is flagged `singleton: true` in the node registry but
  nothing enforces it.** The schema's dedup logic special-cases 6 of the 7
  types marked singleton, omitting node0. The Beta palette will let a user
  create a second root node with no guard.
- **The Node-0 delete confirmation understates the blast radius.** It says
  deleting Node 0 "removes the topbar" — in reality every node is parented
  under it, so confirming cascades and deletes the entire graph. Meanwhile
  "Reset Workspace" (equally destructive — wipes the whole local document) has
  **zero** confirmation at all.
- **Graph runtime only actually evaluates two node families** (`value.*` and
  `math.*`) — every other registered type (`source.*`, `device.*`, `stream.*`,
  most of `universe.*`) is a static values-passthrough with no real computed
  behavior. The `time` node advertises `elapsed/sin/cos/beat` outputs but
  nothing drives them; it's inert. (Feature-completeness gap, not a bug —
  documented here so it isn't mistaken for one later.)
- **Unbounded 409-retry loop** in the client doc-sync path
  (`useProjectDocumentSync.js`): on a version conflict it catches up and
  immediately resubmits with no backoff or attempt cap. Network-bound, not a
  CPU hot-loop, but a client that can never win a version race against a
  faster concurrent writer could retry indefinitely.
- **Upload MIME allowlist is bypassed by Drive-import and commons-import.**
  Direct uploads go through multer's MIME/extension allowlist; the Drive and
  commons import paths write buffers directly with whatever MIME type the
  external source reports, skipping that allowlist entirely.
- **Deploys are not gated on tests.** `ci.yml` and `deploy-vps*.yml` are
  independent workflows triggered by the same push event — a failing test
  suite does not block a production deploy. The only backstop is a post-deploy
  smoke check, which itself silently skips if a repo variable isn't set.
- **No automated, off-box backup exists for production.** The nightly VPS cron
  backs up locally only — already a known, flagged gap (`CURRENT.md`,
  `docs/deploy/VPS_DOCKER_DEPLOY.md`), confirmed still true. Needs a chosen
  destination + credentials before it can be built — not something to decide
  unilaterally.
