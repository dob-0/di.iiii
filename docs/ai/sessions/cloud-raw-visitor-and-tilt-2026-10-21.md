## 2026-10-21 — Visitor and Tilt: what the phone or screen is, as wires

- Two new `bring in` nodes beside Keyboard, both hidden and feed-driven (the Keyboard pattern): `device.visitor` (Phone, Reduced motion, Portrait, Width, Height, Language, Embedded, plus Name, Hue, Id kept in this browser; input New name) and `device.tilt` (X, Y in -1..1, Live; input Range, 30°).
- Browser reads live in `src/raw/components/VisitorFeed.jsx` and `TiltFeed.jsx`, mounted from RawEditor's `runtimeFeeds`; the maths is pure in `src/raw/utils/visitorFacts.js` and `tiltReading.js`. Runtimes (`src/project/nodes/device.visitor|device.tilt/runtime.js`) only read `context.liveOutputs` and answer plain defaults where no feed publishes.
- Phone = `(pointer: coarse)` AND short side < 600 css px (a 768 tablet is not a phone). Embedded = `?embed=1`, `?preview=1`, or framed (a `top` that throws counts as framed).
- Visitor memory: one JSON key `dii.visitor`, every storage touch in try/catch including the `localStorage` getter itself; when storage throws, a per-page memory keeps the same Id/Hue/Name for the visit. Tests cover throw-on-every-call and throw-on-getter; removing the guards fails 4 of them (shown once).
- Tilt: level = the first reading; screen angle 90/180/270 turns the axes (`x = dγ·cos a + dβ·sin a`, `y = −dβ·cos a + dγ·sin a`); a turn re-levels. iOS: `requestPermission()` is called synchronously inside the first `touchend`/`click` on the window, once; denied stays 0,0, not Live. Published at most once per animation frame, rounded to 0.01.
- Numbers: 13 affected test files, 220 tests green; the 5 new/extended files fail (2 runtime cases, 3 missing-module suites) with the source moved aside.
- NOT done: no real iPhone test (a cloud session has none) — the iOS prompt path is tested only against a mocked `requestPermission`; the landscape axis turn is derived from the W3C frame, not measured on a device. Not browser-verified on desktop or phone. The published page (`PublicGraphSurface`) and `/out` pass `liveOutputs={null}`, so neither node reads the visitor there yet — the obvious next step, since the visitor is the point.
