## 2026-10-10 — the shared API helper honours HTTP 429 and Retry-After

- `apiFetch` now retries a GET or HEAD that gets 429, up to twice, waiting the server's `Retry-After` (seconds or HTTP-date, RFC 9110 §10.2.3), capped at 30 s; it never loops without end.
- A POST/PATCH/DELETE, or a wait longer than the cap, is not retried: the error carries `status` 429, `isRateLimited` and `retryAfterMs` so a caller can tell the person.
- Measured: `apiClient.test.js` 13 passed; the 5 new tests failed on the old code (a 429 GET rejected at once, no `retryAfterMs`).
- Owed: the 43 call sites that use raw `fetch` instead of `apiFetch` do not get this; moving them is separate work.
