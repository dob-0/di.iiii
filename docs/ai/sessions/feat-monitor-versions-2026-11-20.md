## 2026-11-20 — Monitor "Versions" tab: latest and past versions of every part

- Why (owner, 2026-11-20): "i want in monitoring version controll, i mean all past versions, and the last that i can track what is working how and what we have from the our softs and thhigs there". Built on the Parts tab (#1303, cb3cf09ba).
- What: a `Versions` tab inside the Monitor (diiii.localhost/admin, key 5; Tasks is now key 6), no new address. Top: each machine/tier's commit against dev (the existing `tierState`). Below: one card per part with the plain state (working / not working / not running / unknown), the running version, the version last seen working, and past versions newest first (date, hash, title, PR number linking to GitHub).
- Past versions: `scripts/partStamps.mjs` `historyFor` reads `git log -10` per part's dirs at PACK time (the installed server is not a git checkout) and `pack-runtime.mjs` writes it into `release.json` `parts[].history`; `serverXR/src/releaseInfo.js` keeps at most 12 sanitised rows per part. The PR number is parsed only from a trailing `(#N)` in the subject (squash-merge form); otherwise null.
- Works / not working: from the part's own probe already read by the Connected panel (`monitorHub.js` `partsBlock`): live/ok = working, off = not working, idle = answered but not started, no probe or not read = unknown. Never a guess.
- Last seen working (the "proven" mark): `createProvenStore` in `monitorHub.js` remembers the commit a part ran when its probe showed it working, in `<dataDir>/monitor-proven.json` (rewritten at most once an hour per commit; memory only when no file). After a bad update the card still names the last version seen working: the rollback target is one look. A part with no probe is never marked.
- Gap fixed (ledger N5845.16, main-desk "commit unknown"): the packer writes `release.json` at the install root, but the server read `serverXR/release.json`; `resolveReleaseFilePath` now falls back to `<root>/../release.json`. Before: the installed main-desk server's `/serverXR/api/health` returned `release` all null (curl this turn). Test: `serverXR/src/releaseInfo.test.js`.
- Parts list: added app (editor shell), server (routes, catalogue), map (Mapping desk), rig, no live probe each. di.bo and MOXIR are not in this repository (own repo / a space), so they are not listed; to be added when their source dirs or a probe route are named.
- Limits: history is as of the PACK of that install, not live git; a part whose probe is null shows "unknown" for works. Shallow clone at pack time gives empty history (shown as "No past versions recorded").
- Tests and pictures: see the PR body.
