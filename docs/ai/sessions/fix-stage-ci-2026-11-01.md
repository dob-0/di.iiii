## 2026-11-01 — Green CI for the stage branch: a pathname in a test, a cross-repo doc path in source, and desk page timers that outlived their test files

- What it is: the fix for CI run 41305326654 on PR #1237 (`stage/copy9-2026-10-31` into dev). Three separate causes, one draft PR into the stage branch, so #1237 turns green without a rewrite. Test-side changes plus one comment in `serverXR/src/stage/showStatus.js`: no page code, no behaviour and nothing a person sees changes, so there is no Wiki change.
- Symptom (read from the job logs and `gh run view`): test shard 3/3 red with 2 failed tests; shard 1/3 red with 13 unhandled errors and no failed test (`Tests 4910 passed`); node-22-compat red with both (`Tests 2 failed | 14517 passed`, 8 unhandled errors); build-and-test red only because it requires them. checks, shard 2/3 and browser-checks were green.
- Cause 1, `scripts/show/checkpoint.test.mjs`: it built a path from `new URL(...).pathname` (`/C:/...` on Windows), which `scripts/noPathnameMainGuard.test.js` refuses.
- Cause 2, `serverXR/src/stage/showStatus.js`: a comment named the di-bo repo's crew-feed doc by a docs path, and `src/docPaths.test.js` resolves every docs path in source against this repo, where that file is not. (The doc exists in di-bo, section "The status push, schema v1"; its reader is `validateStatus` in `lib/card.mjs`; both read through `gh api` this session.)
- Cause 3, the laser desk page tests: six of them boot `desk.js` with `new Function(...)` and the page polls for ever; only `deskCalmStored.test.js` stopped its timers. The others left them running past the end of the file, so the first tick after vitest took `document` or `requestAnimationFrame` out of the global scope threw a ReferenceError with no test running (node-22-compat: "document is not defined" 7 times, "requestAnimationFrame is not defined" once). Vitest counts that as an unhandled error and exits 1 with every test green. Which file is hit follows the timing: `deskSets` (13) on shard 1/3; `deskRemove` (6), `deskSets` (1), `deskCalm` (1) on node-22-compat. Six isolated runs of `serverXR/src/laser/ui` showed none, so the full suite is the arbiter.
- Fix: `fileURLToPath(new URL(...))`; the comment names the doc and its repo and writes no docs path (it says why). New `serverXR/src/testSupport/pageTimers.mjs`, `capturePageTimers()`: wraps `setTimeout`, `setInterval` and `requestAnimationFrame`; `stop()` cancels everything the page armed, lets one event-loop turn pass so an await still in flight re-arms into the wrappers, cancels again and puts the real functions back. The six laser desk page tests and `serverXR/src/showDesk/showDesk.test.js` (its page, `show.js`, re-arms its poll and preview timers the same way) call it at module level and `await pageTimers.stop()` in `afterAll`. The page code is unchanged: a page lives as long as its tab, and the leak exists only because a test outlives its document.
- Guard: `serverXR/src/testSupport/pageTimers.test.js` (9 tests). It tests the helper, and it fails any test in `serverXR/src/laser/ui/` or `serverXR/src/showDesk/` that boots a page with `new Function(` without a module-level `capturePageTimers()` and a `.stop()` on it. The check's own rule is tested on made-up sources (a bare test, a capture inside a hook, a capture nobody stops, and the layout `desk.test.js` has, with the capture below its `beforeAll`). The frame case reads a stub frame queue instead of waiting for a frame: the first version waited, and a helper that did not capture frames at all still passed it.
- Lesson: fix a timing leak for the class, not the file. The first fix of it (commit "test(laser desk): stop the page's timers after the calm-stored test") covered one of six files and CI found the next. A cleanup every author must remember is a guard's job. A local baseline needs CI's installs: `serverXR` has its own `npm ci`, and without it 83 test files fail on a missing module and the baseline lies. Known-fixes entry added.
