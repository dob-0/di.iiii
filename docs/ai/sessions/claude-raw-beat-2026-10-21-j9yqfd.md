## 2026-10-21 — Beat Grid: music to wires (beats, bars and bands) from a baked analysis

- Builds on PR #1073 (Beat as a clock, Oscillator v2); this branch starts from it.
- Bake method written first: `docs/ai/decisions/2026-10-21-beat-bake-method.md` — format v1 (beats, bands at a rate, beatsPerBar, downbeat, strong) and Ellis 2007 onset strength + tempo + DP beat placement. Marked UNVALIDATED: not implemented, not measured against hand-tapped beats on 3 tracks.
- New node `signal.beatgrid` **Beat Grid** (numbers family, beside Beat), reader only: Analysis (JSON text, pasted or wired), Time (seconds; unwired = document clock). Outputs Beat, Phase, Age, Bar, Count, Pulse, Strong, Low/Mid/High, BPM, Clock (an Oscillator on it follows the music's local tempo), Status. Pure function of (analysis, seconds), so it seeks.
- Tests: 12 new (6 for the pure reader, 6 for the node incl. a wired Time, a Text-wired analysis and an Oscillator riding the grid's Phase); with the runtime unregistered 6 of the node tests fail. Affected suites (nodes, graph, registry, palette, label and copy vocabulary, wiki, anatomy): 31 files, 495 tests passed.
- Not done / owed: the baker itself and its measurement; a converter from the two seekable pieces' own arrays (their field names were not readable from a cloud session); the "top 15 % gaps" strong-beat rule (only the every-4th default is here); Sound has no position output, so Time follows the document clock unless wired; no browser check (desktop or phone) — the node has no window, but the inspector's Analysis field holding a long JSON string was not looked at.
