## 2026-11-16 — Monitor: what every machine runs (services, packages, ports, updates), reported live

- New collector `scripts/di/monitorInventory.mjs`: pure parsers, one per source (`pacman -Q/-Qe/-Qm/-Qdtq/-Sl/-Qo`, `checkupdates`, `systemctl show`, `ss`, `flatpak list`, `npm ls -g --json`, `pip list --user`), a Debian branch (`dpkg-query`, `apt-get -s`) and a macOS branch (`brew list/outdated`, `launchctl list`, `lsof`). The macOS and Debian branches are tested with fixtures only; the Arch branch also ran on a real Arch machine.
- Read-only by construction: fixed commands, no shell, no sudo. Nothing secret leaves: no environment values, a unit's ExecStart is cut to the binary's name, a listening port says who can reach it (all / lan / tailnet / loopback) and never an address, unit descriptions are dropped.
- Hooked into `di monitor report` as the `inventory` panel. Collected at most every 6 hours or when a package database's mtime changes (cache in `~/.cache/di/monitor-inventory.json`, mode 600). A report carries `{ hash, collectedAt, counts }` always and the body only when the hash is new or the server asks again. The body is capped at 200 KB and says what it cut.
- Server: `monitorHub.js` keeps the last inventory per host (apart from the report, so a hash-only report keeps it; it leaves with its host after an hour). A report whose hash has no stored body is answered `inventoryWanted: true` and the reporter sends the body once more in the same round. `GET /api/monitor/inventory/:host` returns the body behind the same owner-only gate as every `/api/monitor` route; the snapshot and the stream carry only the summary.
- The report's own 256 KB limit is unchanged; the inventory body is weighed on its own (256 KB).
- Tests: 28 parser/collector/panel tests (`monitorInventory.test.mjs`, made-up fixtures), 2 new in `monitorReport.test.js`, 3 in `monitorHub.test.js`, 2 in `monitorRoutes.test.js`; the existing monitor route, stream and store tests pass.
- Not touched: `src/` (the Monitor's layout is being rebuilt elsewhere). The panel's JSON contract is the next step for that work.
