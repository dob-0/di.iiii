## 2026-11-21 — the Agents box lists the live agents of every machine, each named by where it runs

- Why: studio-mac's Agents box and "Agents at work" list showed only its own agent (1 live of 81 sessions) while aylmo's report in the same account held 7 live agents. Owner words: "there are still not the all session , i work with the studio mac and there no agents" (N6026), "we need to one brain in di server and everything is connected" (N6027).
- What: `serverXR/src/monitorHub.js` `agentsFor` lists this machine's agents and those of every other machine from reports the hub already holds (its own reports and the signed-in account's rows from dev): each row carries `machine`; a machine is known by the first word of its name (an IP address is one name) and, with several reports, by its best one (a list, then a failed list, then none, then a stale report; the newer first); a session is listed once; a machine whose list is stale, missing or unreadable is named with the reason (`machines`), also this machine when its own list cannot be read (its scan failed or took longer than 9 seconds; the other machines' agents are then still listed); this machine's own agents are never cut, another machine's are cut at 50 per machine and at 150 in all (this machine's counted); `live`, `busy`, `total` and `accounts` are recounted. No probe and no model call is added. The page (`MonitorSection.jsx`) groups by "machine / account", counts machines in the subtitle, says why a machine is not in the list, and names the machine on every dot and in the list. The change feed (`monitorFeed.js`) knows an agent by its session id and says an agent started or ended only if the machines list stood the same way in both snapshots and no list was cut (a machine whose report goes stale or comes back moves its agents in or out of the rows; nothing started or ended). Wiki bullet and known-fixes entry included.
