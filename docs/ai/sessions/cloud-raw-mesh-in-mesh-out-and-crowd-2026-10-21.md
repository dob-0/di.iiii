## 2026-10-21 — Mesh In and Mesh Out: the graph talks to the mesh, one shared browser client

- New `src/raw/utils/meshClient.js`: the one browser client for serverXR's `/serverXR/mesh` hub (group = the hub's `room`, node id `web-*` so it never claims the reserved `keeper-*`, reconnect 1 s doubling to 10 s and back to 1 s once up, a fresh id after close 4409 "Node id in use", publish refused while not up, nothing queued). Plus the pure pieces the nodes use: `checkMeshPayload` (Min/Max range when Min < Max, Allowed comma list, Max Length) and `createSendGate` (one send per interval, latest wins).
- Two nodes, colocated runtimes reading the feeds' report through `context.liveOutputs` (the MIDI Out shape): **Mesh In** (`device.mesh.in`, bring in: Value, From, Time, Signal as a rising count, Up, Status) and **Mesh Out** (`device.mesh.out`, send out: Value on a Channel, at most once per Interval, 200 ms default, 50 ms floor, only while up, a value re-sent only when it actually changed, the current value once on reconnect). Empty Group = `<space>/<project>`, so every screen on the same project meets. Sockets live in `src/raw/components/MeshFeeds.jsx`, mounted in RawEditor's runtime feeds beside MIDI Out.
