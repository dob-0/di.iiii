## 2026-11-20 — the monitor sender timer names `~/.di/current`, not a version folder

- Why: main-desk stopped reporting at 23:30 on 11-19. Its unit named `~/.di/versions/0.4.4-dev.ee04a819/cli/cli.mjs`; `di update` keeps the new version and the one before it, so the folder survived the update at 21:55 and was removed by the one at 23:30; every run after it failed with "Cannot find module" (161 runs to 00:55); the timer still showed `active`. A machine that stops reporting looks like a machine that is off, so the signed-in Monitor lost it.
- What: `stableCliPath` in `scripts/di/monitorReport.mjs`; `installTimer` writes `~/.di/current/cli/cli.mjs` when that link leads to the running copy (an installed di), and the running file otherwise (a source tree), and in that second case prints a note that the unit stops when that folder is removed. `installTimer` takes `diRoot` and `cliFile` so a test can build an install in a temp folder.
- Tested: `npx vitest run scripts/di/monitorReport.test.js`: 23 passed (8 new). An independent review ran 24 one-line mutations of `monitorReport.mjs` against that file: 18 were caught and 6 were not (the note's link and advice sentence, the default install root, and the two things `runMonitor` does for `install-timer`: pass `--remove` on and not pass a `cli` of its own). The tests added after it catch all six, and the new guard against a call without `cli` (7 re-runs, each fails one test); eslint on both files clean. Not tested: a real `di update` on a machine. The proof is a successful journal run after the SECOND update that follows a reinstall of the unit (the first keeps the old folder, so it proves nothing).
- After it lands: every machine that already runs the timer re-runs `di monitor install-timer` once from a version that contains this fix (main-desk first); `scripts/monitor-join.sh` already runs it on a machine that joins.
- Not done: the macOS launch agent (PR #1322) needs `stableCliPath` for its `cli` default, and it conflicts with this change in `installTimer` and its tests (rebase after one of them lands); `di monitor install-timer` has no platform check (on macOS and Windows it still writes systemd files; #1322 adds the launch agent); the unit's node path is also a versioned folder on main-desk (`~/.local/opt/node-v22.23.2-linux-x64/bin/node`); no alarm when a timer's last run fails.
