## 2026-10-21 — QR Code: a Raw node that draws a live code for an address

- New node `view.qrcode` (**QR Code**, family make, render hidden): Text in, Correction (L/M/Q/H, default M) in, Picture out as a texture wire — the Webcam Frame's kind, so a Plane, an Image panel or Picture Out shows it. Text left empty encodes this tier's own address (`window.diiPageOrigin`, else `location.origin`), read on every pass, so a project moved between tiers draws that tier's code, never a dead one.
- Encoder: qrcode-generator 1.4.4 (MIT — `LICENSE` fetched from the upstream repo; the file header and `package.json` say the same). Vendored for pages at `public/vendor/qrcode-generator@1.4.4/` with its LICENSE and sha256 in `VENDOR.md`; the node bundles the npm copy at the exact same version. `qrCode.test.js` holds both files to the one sha256 (`18ae399f…`), so they cannot drift. jsdelivr was refused by this session's proxy, so the sha is of the npm registry's file, not a CDN download.
- `qrCode.js` is pure (text → module grid → RGBA bytes, 4-module quiet zone, whole-pixel modules, ≤ 1024 px). `runtime.js` keeps one `DataTexture` per node and remakes it (disposing the old one) only when text or level changes.
- Tests (round trip through jsQR 1.4.0, already a dependency): 4 texts × 4 levels decode back exactly, UTF-8 included; version-40 limit at H is 1273 bytes (1274 → null); finder patterns in three corners, none bottom-right; the texture is the upright picture row-flipped. jsQR reads mirrored codes too, so orientation is checked on the pixels, not by decoding. Node tests: bare → this origin; diiPageOrigin wins when Text is empty; a wired String wins; same text returns the same texture object; a new text disposes the old one; too-long text → null. Without the runtime wired: 6 of the node tests fail; with the flip removed: 1 fails.
- NOT done: no browser check on desktop or phone (cloud session, no tier to look at); nobody scanned the texture from a real phone off a real wall. The four works that hand-build a code (the wall board's dead baked code, open-jam's offline code, wall-drive's text-only "scan", di-jet's control panel) are not moved onto the node — each is a project edit for the owner. A deleted QR Code node keeps its texture in a module-level map until the page reloads (one texture per node id, ~4 MB worst case at 1024²).
