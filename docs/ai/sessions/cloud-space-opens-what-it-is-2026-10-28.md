## 2026-10-28 — a project opens what it is: its scene, its code page, or its plain project view (never an empty 3D scene)

- Bug (owner, dev.diiii.xyz): a new space such as cinema-house, with one project and no scene, always landed in the 3D view, because `entryView` defaults to `scene` for every document, and a space with no front door fell through to the editor.
- Opening a project: `src/shared/openingView.js` `resolveOpeningView(document)` decides from what the project holds — a stored `code` or `fixed-camera` choice is kept; else objects or nodes → scene; else code → code; else the plain project view. `PublicProjectViewer` uses it. The plain view shows the project's name and its pictures, scrolls, and offers a session that can edit three links: "Add a scene" (the editor), "Write code" (`?open=files`, the Code window; `StudioShell` draws it even on an empty project) and "Add pages or pictures" (`?open=create`).
- Opening a space: a `/{space}` with no front door opens its only project, its project list (`SpaceContentsPage`), or `EmptySpaceView` when it holds nothing (`SpaceSurfaceApp.jsx`). It keys on the space having answered, not on the last poll succeeding, so one failed poll does not swap in the editor. The editor is still shown when the list of projects cannot be read.
- Creating a project: Studio's "+ New project" lands on `/{space}/p/{id}` (`src/studio/utils/newProjectEntry.js`), not the editor. The Nodes tab still opens the node editor.
- Limit: a stored `scene` cannot be told from the schema default (the server stores normalized documents), so `scene` on a project with nothing in it opens the plain view.
- Docs: wiki article `layers-one-at-a-time`, `docs/ai/known-fixes.md` entry.
