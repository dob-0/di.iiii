## Fixture library part 4: a project loads only the fixture types it uses

- Split of PR #914, part 4 (part 1 = #1039, part 3 = #1042). New `src/rigbuild/types/projectTypes.js`: `typeIdsUsedBy(entities)` (a lamp's `components.fixture.type` and the types on its rental list), `loadProjectLibrary(entities)` (one dynamic import per type file, cached) and the hook `useProjectLibrary(entities)` (PENDING while the first types load; a new kind placed keeps the types already drawn while its file loads, then adds it).
- Readers moved: `useRigLookEntities` (room and Studio viewport), `RigBodies`, `RoomRigSteps` use the hook when no `library` is passed. `useRigAutoPatch` (Studio) loads the room's types when a patch runs (`loadProjectLibrary`), so a lamp of a kind just placed is patched with its own type.
- The Studio's walk hand (`StudioWalkBuild.jsx`) offers every type, so it is now its own lazy chunk (`WalkHand.jsx`): the whole library is fetched when a walk starts, not when a project opens. The tool surfaces (build, plot, cards, equipment, patch sheet, visualiser) already were lazy routes and keep the whole library. This also answers the plan's open question for the Studio: the tools take one bundled chunk (the eager glob), not 14 requests.
- Rules that need a type outside the entities: none today. The laser safety checks key on `LASER_TYPE_IDS` of the lamps' own types, which are in the entities. A rule that needs one adds it in `typeIdsUsedBy`.
- Guard: `projectTypes.test.js` lists the only files that may import the whole library (`types/index.js`); a new importer fails the test and is a decision.
- Measured (agent screen, one rig project: `moxir-v2-11`, 140 objects, 5 lamp types + 4 more on its rental list = 9 of 13; 3 cold runs each, median). Dev servers, first load, fixture-data requests (`types/library/*.json`, JS-wrapped JSON): origin/dev 13 types, 441,778 B (room) and 441,778 B (Studio); this branch 9 types, 366,611 B and 366,611 B (-17 %). Production build (minified, `vite build`): origin/dev one chunk 65,420 B raw / 16,722 B gzip / 14,099 B brotli; this branch, the 9 types plus the index: 59,903 B raw (-8 %) / 24,932 B gzip (+49 %) / 21,816 B brotli (+55 %) in 10 requests; a 3-type room (the unit test's): 27,331 B raw (-58 %) / 10,367 B gzip (-38 %) / 8,983 B brotli (-36 %). JSON.parse of the same data in the browser: 0.7 ms (13 types) vs 0.6 ms (9) vs 0.2 ms (3), at the timer's 0.1 ms grain: parse time is not the cost, bytes and requests are. Break-even against one chunk is about 5-6 types: below it a project downloads less, above it more (gzip compresses one chunk better than 13).
- Seen: room page and Studio of `moxir-v2-11` on this branch and on origin/dev look the same (di-health/merge-proof p4-room/p4dev-room, p4-studio/p4dev-studio). In a scratch copy of the project (no rental list): the Studio opened with 5 types fetched; a lamp of `up-q108s` placed by another person arrived live and its file was fetched without a reload; Walk fetched the other 8 types (the hand); placing a hazer rendered its body (p4-add-type.png).
- Not tested: a phone, XR, a real production URL; the pixel-level difference between the room pictures (compared by eye, the sync-status chip differs); the scene deck / Perform pages.
