## C. Confirmed, waiting for the owner

- **Studio zoom stops at the minimum distance.** Real on `dev`: with camera-controls 2.10.1 and Studio's numbers the camera moved 0 m between 40 and 65 wheel ticks. The fix already exists: #748 (`infinityDolly`, green, open since 10-04, after "i still can't fully zoom"). R1 measured a side effect the PR does not mention: the same prop also removes the zoom-OUT ceiling in Studio (500 m today; 3,646 m after 65 ticks). Inside MOXIR's SmartView a boundary holds it. Decide: merge as is, or bound the outward zoom in Studio. Library-level measurement (jsdom, synthetic wheel), no GPU — noted on the PR.
- **#726 on hosted tiers** (from its own text): every page is "away", so an operator set to run on the hosted server's machine runs nowhere. Read before merging.
- **Gating dev-tool advisories in CI** (`--include=dev`) would turn every advisory in a build tool into a red deploy — what the production gate did to `dev` on 2026-10-06 (`proxy-addr`, then `sharp`).
- **Self-update integrity** (found by reading, no test): an https release with no `checksums.txt` is installed unchecked; the checksums sit beside the tarball, so they guard against damage and not against a forged release (there is no signature); nothing rolls back by itself if `di up` fails after the switch (`--rollback` by hand). Signing is a design call (Sigstore cosign or GitHub artifact attestations; an A/B update with a post-switch health check).
- **A design limit the visibility spec should name:** project ids are global and come from slugs, so anyone who can create a project can learn that a private project with that id exists (the create route answers 409 "taken"). "A visitor cannot even learn that it is there" holds for visitors, not for people who can create projects.
- **Two low-severity answers that confirm more than they should** (found by reading, no test): the restore route answers a non-member with 403 and the space id where it should answer 404, so a trashed private project can be confirmed (`projectRoutes.js`, being edited by the follow-carry branch), and the proposal's 409 names the space that holds a project id.
- **Not seen on a screen** (no lane may start a browser): the Keeper in Raw (#809), the 1 px padding on the Camera In refusal text (#726), `away: true` from a real second computer (#726), the unsaved-changes banner and Retry replay (#737).

## F. Method notes for the next person

- `git cherry origin/dev <branch>` says "not landed" for any squash-merged branch. Check `gh pr list --state all --head <branch>` before calling a branch stranded.
- The pre-push gate wants `CURRENT.md` identical to `origin/dev` (a branch stacked on an older branch must restore it) and a session note named for the LOCAL branch. Pushing a PR branch from a differently named local branch trips the second one.
- `docs/ai/known-fixes.md` is edited at the same place by nearly every PR, so open PRs re-conflict on it. A built-in `union` merge driver for that one file (gitattributes) is a candidate; unvalidated.
- PR validation lists that name directories miss `src/copyVocabulary.test.js` and `src/styles/spine.test.js`, which are the two guards that failed on #726 and #737. Run both before pushing a branch that edits `wikiContent.js` or a stylesheet.
- Heavy jobs on this laptop go through one queue (`~/.local/state/di-locks/heavy-run.sh`, CPU ≤ 80 °C). Two other lock paths exist and exclude nothing; waits were 5–15 minutes per job (flock is not first-in-first-out).
- A check-then-await-then-insert on a unique key is a bug class worth a grep elsewhere (`known-fixes.md`).
